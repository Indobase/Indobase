## Getting Started

To ensure a positive and inclusive environment, please read our [code of conduct](./CODE_OF_CONDUCT.md) before contributing. For help setting up the code in this repo, follow [DEVELOPERS.md](./DEVELOPERS.md). For the docs site, see [apps/docs/CONTRIBUTING.md](./apps/docs/CONTRIBUTING.md).

## Issues

If you find a bug, please create an Issue and we'll triage it.

- Please search [existing Issues](https://github.com/Indobase/Indobase/issues) before creating a new one.
- Please include a clear description of the problem along with steps to reproduce it. Exact steps with screenshots and URLs really help here.

## Pull Requests

We actively welcome your Pull Requests! A couple of things to keep in mind before you submit:

- If you're fixing an Issue, make sure someone else hasn't already created a PR fixing the same issue. Likewise, make sure to link your PR to the related Issue(s).
- We will always try to accept the first viable PR that resolves the Issue.
- If you're new, we encourage you to take a look at issues tagged with [good first issue](https://github.com/Indobase/Indobase/labels/good%20first%20issue).
- If you're submitting a new feature, open a [Discussion](https://github.com/Indobase/Indobase/discussions/new/choose) to align on scope before opening a PR.
- Please use the PR message template and provide detailed context for quicker review. PRs without clear problem statements may be closed.

Prior to submitting your PR, please conduct the following pre-flight checks:

- Run `pnpm run build` locally (or the relevant package build) to ensure your code builds successfully.
- Ensure that formatting and lint checks pass for the areas you changed.

Running these before you create the PR will help reduce back and forth with the team.
