## Learned User Preferences

- Use Indobase branding everywhere (UI, docs, packages, Builder, marketing, and ecosystem apps); zero Supabase naming in the shipped bundle—including route paths, boltAction types, and filenames—not icons/logos or "fork/clone of Supabase" language. Same bar for forked products: zero user-visible Meteroid, Notifuse, Postiz/Gitroom, Rybbit, Penpot, OpenCut, Mattermost, ONLYOFFICE, Gameplan, or Frappe Suite/Drive/Writer/Sheets/Slides/Meet naming (titles, footers, sponsor/social links, OAuth client names, swagger, emails, extension manifests). Keep LICENSE/NOTICE AGPL attribution; do not mass-rename Go import paths that break builds. Marketing sign-up/dashboard CTAs must land on `studio.indobase.in` (`apps/www` `getSignUpUrl`), never `indobase.in/dashboard`. Auth sign-in/sign-up primary CTAs use brand blue (~`#3B8FD6`), not cream/gold warning styling.
- Studio/Builder/control-plane default is staging-first (`staging` → `indobase.fun`); promote to `main`/Vyom only when asked. (Temporary prod-only window ended 2026-07-30.)
- Do not commit, push, or deploy unless the user explicitly asks; when they say finish first and push at the end, complete the full implementation before any commit/push.
- User grants VPS SSH access for infra fixes and expects agents to work autonomously until issues are resolved. Prefer cheaper Builder preview/speed fixes that reuse current Vyom infra (server build + draft preview / static hosting) over Emergent-style per-session K8s warm pools unless they explicitly ask for that scale.
- Product goal is Supabase Cloud parity, including multi-tenant architecture with a dedicated database per new project; dedicated/isolated tenant stacks are for paid users—free remains project-based. Prefer fleet-wide permanent fixes for tenant data-plane and connection issues over per-project patches. Product must meet India DPDP (Digital Personal Data Protection) compliance requirements.
- Backend Studio unlocks at Pro+ (Free/Basic see upgrade prompt). Plan ladder: Free ₹0 / Basic ₹499 (frontend/static, no Studio) / Pro ₹1,999 (Studio unlocked) / Studio ₹6,999 (team/agency) / Enterprise custom. Free→Basic is vanity (domain/badge); Basic→Pro is necessity (auth/backend); Pro→Studio is team. Plan-keyed client maps/constants must include `basic` and `studio` (legacy `team` → studio); manual plan changes update `saas.organizations.plan` within the DB check constraint.
- Project root stays a product chooser (Builder / Studio / Payments / Marketing / Analytics). Chooser CTAs say "Open Builder" / "Open Studio" (no Indobase prefix). Marketing hub launches Email, Social, Design, and Video. Studio also grows org/project Team chat (**Indobase Discuss**, Mattermost-backed), collaboration workspace (**Indobase Workspace**: Files, Docs, Sheets, Presentations via document editor), plus CRM, Helpdesk, and Domains—Workspace does not replace Discuss chat; the ecosystem must feel like one OS product, not bolted-on forks. Design (visual editor) should track Canva-like create/home UX (category rail, search, size presets) with a large multi-category template catalog. Studio session SSO is the only operator login for ecosystem apps—no separate product email/password UIs; cold visits to apps like Email must not blindly bounce to Studio without a product landing or session resume CTA; Builder remains reachable even from the Free-plan Studio upgrade gate. Customer-facing positioning is an agentic business OS (Studio + Builder + Payments + Analytics), not an AI-builder-only story. Domain reselling (name.com-backed **Indobase Domains**) is intentional so users can buy domains in-product.
- Builder builds from the user prompt and the coding model only — no predefined starter-template import or auto-select. When hardening Builder, fix whole-builder pipeline issues (build/deploy/chat), not single-prompt-only patches. Builder must not expose provider/model pickers in the UI; route LLMs server-side only (`/api/models` returns empty lists; hide Cloud/Local Providers settings).

## Learned Workspace Facts

- Indobase is a SaaS control plane (Studio `/api/platform/*`, `saas.*` schema, Razorpay billing) on a Supabase-compatible data plane (Kong, GoTrue, PostgREST, per-tenant stacks). Platform `/api/platform/auth/*` must use tenant-scoped GoTrue on dedicated `isolated_stack` projects, not control-plane Kong. `decryptString()` must try both `PG_META_CRYPTO_KEY` (tenant connection strings) and `CRYPTO_KEY` (project API keys). On Vyom `.249`, both keys must stay the **32-char** values from `/opt/indobase/docker/.env`—wrong-length (e.g. 44-char) keys cause fleet-wide `Failed to decrypt value` on project APIs; verify via health `cryptoCanary` after Studio rolls. New projects get unique per-project JWT secrets; shared-secret backfill is intentionally breaking and dry-run by default via `POST /api/cron/backfill-project-jwt-secrets`—do not leave `saas.projects` JWT keys rotated ahead of unrepaired tenant stacks. `saas.projects` has no `updated_at`; data-plane-repair / plan-lifecycle must use `coalesce(data_plane_last_provisioned_at, inserted_at)`. `saas.organization_members` has composite PK (`organization_id`, `gotrue_id`)—order scans by `inserted_at` then `gotrue_id`.
- Published npm SDKs are `@indobaseinc/*` (`@indobaseinc/js` is the root wrapper; unscoped `indobase-js` is not owned by this org). Studio Docker/CI still imports workspace `indobase-js` until `@indobaseinc/*` is declared in `apps/studio/package.json`; undeclared `@indobaseinc/*` imports break docker-publish.
- Per-tenant data planes are Docker Compose stacks on Vyom **103.190.92.248** (provisioner `:8787`, wildcard `*.indobase.in`), provisioned via `data-plane-provisioner` with `repair-stack` / `repair-fleet` self-healing. Do not use Hostinger `187.77.30.165` for new workloads.
- Control plane and tenant DBs share one Postgres host: keep `POSTGRES_PASSWORD` and `SAAS_DATA_PLANE_AUX_ROLE_PASSWORD` aligned; fleet `repair-stack` must ALTER ROLE `authenticator` only once cluster-wide, not per tenant. Missing `saas.project_edge_function_secrets` breaks data-plane auto-repair.
